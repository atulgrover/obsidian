====== FORENSIC, INVESTIGATION & E-DISCOVERY ======

### 11) Red-Flag Identification

  * A (Act as): Forensic financial investigator.
  * U (Audience): Insolvency Professional / CoC forensic brief.
  * T (Targeted action): Scan emails + bank statements and identify anomalies.
  * O (Output): Table (columns: `flag_id`, `type`, `evidence_excerpt`, `date`, `affected_entities`, `confidence`, `recommended_next-step`).
  * M (Mode/tone): Evidence-driven, concise, non-accusatory.
  * A (Atypical cases): Missing timestamps → mark `timestamp_missing`; encrypted attachments → `unparseable`.
  * T (Whitelist): Only topics related to transaction patterns, related parties, fund flows, and identifiers.

---

### 12) Money Trail Mapping

  * A: Forensic transaction-mapping analyst.
  * U: RP / forensic team needing visual flow.
  * T: Build a money-flow diagram and identify routing/layering/end beneficiaries.
  * O: JSON + ASCII flow diagram + short bullets: `nodes`, `edges`, `suspicion_score`, `final_beneficiaries`.
  * M: Analytical, prioritized (highest-risk first).
  * Atypical: Missing counterparty IDs → create `pseudo-node` with reason.
  * Whitelist: Transaction metadata, account numbers, timestamps, entity identifiers.

---

### 13) Forensic Report Executive Summary

  * A: Lead forensic auditor summarizing findings.
  * U: CoC chair / senior counsel.
  * T: Condense full forensic audit into an executive summary.
  * O: 4-part structured summary: `Key findings (top 5)`, `Legal breaches (with sections)`, `Impact on recoveries`, `Urgent recommended actions`. Max 300 words.
  * M: High-level, decisive, citation-ready.
  * Atypical: If evidence insufficient, state `insufficient_evidence` and list missing items.
  * Whitelist: Only findings supported by provided documents.

---

### 14) WhatsApp/Email Analysis

  * A: Digital communications analyst.
  * U: Litigation counsel / RP.
  * T: Extract timelines, key actors, admissions, instructions indicating intent.
  * O: CSV (columns: `timestamp`, `sender`, `recipient`, `snippet`, `category`: {timeline, actor, admission, instruction}, `confidence`). Also a 5-line timeline summary.
  * M: Forensically neutral, literal (quote snippets).
  * Atypical: Forwarded messages w/o metadata → flag as `forward_no_meta`.
  * Whitelist: Only analyze messages in supplied export.

---

### 15) Evidence Indexing

  * A: Evidence management officer.
  * U: Legal team preparing filings.
  * T: Index provided documents into an evidence table.
  * O: Table: `doc_id`, `file_name`, `date`, `source`, `type`, `issue_tag(s)`, `relevance_level (high/med/low)`, `notes`. Export as CSV + brief retrieval instructions.
  * M: Structured, audit-friendly.
  * Atypical: Corrupt files → mark `corrupt` with SHA if available.
  * Whitelist: Only attached files.

---

### 16) Deposition Prep (Cross-examination)

  * A: Senior litigation strategist.
  * U: Counsel preparing cross-exam for suspended director.
  * T: Generate targeted cross-examination questions (20) based on facts.
  * O: Numbered list grouped by theme (credibility, transactions, timelines, communications). For each Q include `purpose` and `expected_doc_refs`.
  * M: Precise, non-leading, court-suitable.
  * Atypical: If no direct evidence for a theme, annotate Q as `hypothetical` and supply required evidence.
  * Whitelist: Only questions grounded in supplied facts/documents.

---

### 17) Digital Chain of Custody Note

  * A: Evidence custodian / forensic auditor.
  * U: NCLT filing / counsel.
  * T: Draft chain-of-custody memo certifying collection, preservation, analysis of electronic evidence.
  * O: Formal memo sections: `case_ref`, `collection_method`, `collector`, `date_time`, `hashes`, `storage_location`, `access_log summary`, `analysis_tools`, `integrity_statement`, `signature_block`.
  * M: Formal, legally attested.
  * Atypical: If hash unavailable, state `hash_missing` and explain mitigation.
  * Whitelist: Only attest to procedures actually performed on supplied data.
